# 持久终端会话（Agent 1.15 起，当前 1.16）

打开 Agent 终端会恢复该账户在该服务器的最近会话；首次使用时创建会话。关闭窗口、“离开并保留会话”、浏览器断网或刷新都只断开附着连接。重新连接会获取新票据并恢复原会话，不重发之前的输入。

“新建”创建另一份会话；“会话列表”刷新当前账户的会话。“结束会话”会终止其中的任务，需要单独确认。会话已经结束时不会自动复活或重跑命令。每账户最多 16 个会话，每服务器最多 64 个会话；活跃任务不会因离开页面被自动清理。

服务器上使用独立的 `ppeelink-terminal.service` 运行 tmux。它不从属于 Agent unit，因此 Agent 或面板服务重启不会终止会话。该 unit 由 Agent 启动时准备，已部署的 Agent 自更新后也走相同准备流程；缺少 tmux 时使用系统包管理器安装，失败时页面明确提示保护尚未就绪，可重试。当前安装准备支持 Debian/Ubuntu 的 apt 及 dnf/yum 系统；必须使用 systemd。

服务器重启、断电或 tmux 服务自身退出会结束运行中的进程，系统不会把原任务重新执行。回滚 Agent/面板时应保留独立 tmux 服务，不要附带 stop、kill-server 或删除 socket。卸载 Agent 也不会顺手清理仍在运行的持久任务；需要清理时先确认并结束会话。

默认通过页面选择会话，tmux 自身的前缀快捷键已关闭，避免当前画面和页面选中会话不一致。终端中的管理员拥有服务器权限，仍能明确执行系统级 tmux 命令；这不是一个隔离 root 权限的沙箱。

快速指令以只读诊断为主，先填入可编辑草稿，再点击“发送并执行”。确认终端已回到命令行后执行，避免把命令发送给安装器或编辑器。安装和系统配置收在扩展工具，入口脚本固定版本并校验摘要，其内部软件包与后续下载仍由上游管理。原有 Compose 删除数据卷快捷项已移除；会清理远端备份的通用备份脚本入口已停用，仅提供配置位置检查。

验证包括真实 HTTP/JWT 与 Agent 连接、一次性票据、账户隔离、队列拥堵、暂停 tmux 输入、连接断开与实际 Agent systemd 重启下的 PID/进度连续性，以及 320/768/1024/1440px 浏览器检查。完整 Go 测试仍有本次改动前的 15 个失败项，未增加新失败；竞态检测未运行，因为当前构建环境没有可用的 CGO/C 编译器。具体结果和已知失败名单见部署记录。

1.16 增加 Ubuntu 20.04 / tmux 3.0a 兼容，使用带 PIDFile 的独立 forking 服务。已有健康终端服务继续运行；旧版缺少的 -N 参数通过能力探测跳过，会话创建后校验服务进程所属 unit。附着就绪须等待客户端与目标会话绑定，避免旧版启动阶段吞掉首次输入。
