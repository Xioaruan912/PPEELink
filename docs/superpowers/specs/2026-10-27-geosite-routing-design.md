# Website category routing
User selected category routing. Extend existing ordered per-inbound domain rules with a category match, reusing Xray geosite data included with the installed core. Offer a fixed set verified against Xray 26.3.27: google, youtube, netflix, openai, telegram, github, microsoft, apple, cn, geolocation-!cn. Do not infer where traffic should go; user explicitly selects destination. Exact, suffix and category entries remain in one ordered list. Match the first entry, then retain existing default. Continue accounting and fail-closed behavior. Category list is version-dependent; do not automatically update geodata separately. Agent Xray config self-test rejects absent/corrupt datasets and leaves last running config in place; UI must disclose this. Require capability 4 for category entries, so capability 3 cannot silently ignore rules. Existing routes/JSON unchanged. For IP or invisible names default applies.
