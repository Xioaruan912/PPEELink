# Agent 服务端中转
用户已授权实现、推送并部署两种模式，并移动菜单。
1. 纯端口转发：Agent 原生 TCP/UDP 固定目标转发，监听端口固定，客户端不需要链式代理；订阅生成入口地址并保留上游协议认证参数。更换不同凭据的落地仍需更新订阅。
2. 固定入口网关：复用自建入站和独立 Xray，入口凭据保持不变，面板切换 Reality/HY2 出口。现有账户、配额和网站分流保持生效。
3. 最终用户修订：删除客户端链式代理，只保留纯端口转发和固定入口网关。移除页面、批量 chain 操作、节点 flag 字段及客户端生成逻辑；升级时清理旧关系，保留节点链接、ID、分组、订阅引用和其他连接开关。节点一键诊断归网络诊断，旧 URL 可继续访问。
4. 新转发默认不创建生产规则；发布功能并升级在线 Agent 能力，用户通过页面选择入口和落地。
5. 原生转发具有端口冲突/循环/公网目标检查，连接和 UDP 会话上限，会话固定上游，变更只作用于新连接，状态/流量回报，监听绑定或临时 DNS 失败保留旧规则；目标删除、暂停或配置成循环时停止受影响线路，管理连接断开不停止规则。
6. 诊断沿生成的香港入口实际访问目标；网关使用已有自动节点诊断。统计显示线路流量，不能把加密原始转发流量伪称按用户或网站统计。
7. 风格沿用当前灰白、深色文字、小面积蓝色；手机单列，不出现技术占位名。
8. 转发和网关节点名称使用用户输入，不追加“中转”、服务器名或端口。网关名称必填，同名网关保存时提示更名。
9. Agent 确认转发后立即失效节点概览缓存；缓存页激活/可见时刷新，活动页定期静默读取，离开页面停止。固定入口网关与同机已有直连入站分别生成节点，切换落地保持入口身份。
