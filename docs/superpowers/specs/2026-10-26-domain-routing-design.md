# Server-side website routing
User approved the proposed website-to-egress feature and asked to start. Each inbound has up to 32 ordered domain rules: exact host or host plus subdomains, destination either server direct or an existing VLESS Reality TCP/XHTTP exit. Unmatched traffic retains the inbound default. Exit failure never falls back. Domain/IDNA normalization, invalid inputs, missing exits, self-reference and graph cycles fail validation. Agent capability 3 required. Existing configurations without rules retain their revision and behavior.
Approaches: native Xray routing alone loses metering path; matching in the collector loses sniffed-domain routing. Chosen: native routing selects the exit before metering, using per-rule authenticated collector identities and existing egress bridges, so original validated destination and inbound accounting remain unchanged. No client config changes required. IP-only/encrypted hostname traffic without an observable domain uses the default; UI explains this boundary.
Neutral responsive ordered rule editor in inbound drawer, explicit fallback label, no global presets or changes to existing live routes. Scope includes API persistence, resolved Agent spec, both metered/unmetered configuration, graph-cycle prevention, unit/real-core tests, deployment and Agent upgrade.
